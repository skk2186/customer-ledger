# 产品规格：阶段三 Excel 导出与旧账迁移

## 目标

让普通会计用户在本机完成阶段二记账闭环，并安全地导出当前账务、预览旧 `.xls` 内容、确认映射后导入旧账和核对结果。

## 用户流程

1. 新增或选择有效客户。
2. 新增发货；空数字按 0 处理，可同时录入初始收款。
3. 后续新增收款，可暂存预收、指定发货或按日期和 ID 自动分配。
4. 在客户账目查看固定发货明细、系统合计、收款和预收。
5. 需要时编辑原始发货字段，或通过文字确认作废；作废不物理删除。
6. 在只读“客户汇总总表”按截至日期查看全体客户。
7. 在客户账目或汇总页导出 `.xlsx`；全部账目导出时首个 Sheet 固定为客户汇总总表。
8. 在“旧账迁移”选择 `.xls`，先看试算结果和异常，确认客户映射及预收后，系统先备份本机账库，再在一个事务中导入并显示对账结果。

## 规则

- 金额使用整数分，吨位和平方数使用百分之一整数单位；用户输入由 Decimal 安全解析，拒绝浮点形式、科学计数法、NaN、Infinity、非法文本和三位以上小数。
- 原始金额/数量/收款非负，Payment 金额必须大于 0；派生应收、欠款和净余额可为负且不截断。
- 应收款 = 总货款 - 运费 - 卸车费 - 退板金额 - 问题扣费；退板吨位、平方数不参与应收。
- 本单实收为有效 PaymentAllocation；客户总收款为有效 Payment；客户净余额 = 有效发货应收 - 有效收款 - 有效抹零。
- 付款方式只允许银行转账、微信、支付宝、现金、其他；付款方式和说明分开保存。
- 暂未付款不创建 0 元 Payment；超额收款保存完整 Payment，不能丢失，多余部分是未分配预收。
- 写操作在服务层事务中完成；提交令牌唯一，重复提交不产生第二套记录；失败完整回滚。
- 已作废记录可查看并明确标记，但不计入当前合计；审计摘要不保存完整敏感说明。
- 导出只生成 `.xlsx`，禁止外部链接、公式、宏、VBA、Power Query 和网络依赖；客户 Sheet 名不截断、不自动改名。
- 旧表迁移区分标题、表头、业务日期行、空行、合计行、备注/预收行和未识别行；遇到合计行不会停止扫描，A:M 是正式业务区，N 列以后只形成异常提示。
- 旧表中的应收、欠款只用于迁移对账；导入后应收和分配金额由现行计算服务重新计算。预收、扣减和付款方式不清楚的记录在用户确认前不写入正式账务。
- 历史汇总 `.xls` 只作为聚合核对参考，不作为 Customer、Shipment、Payment 或 Allocation 的直接导入来源。
- 导入来源身份至少由源文件 SHA-256、工作表和原始行号组成；同一来源再次执行不新增记录，文件哈希变化不按日期和金额静默去重。

## 阶段边界

本阶段不实现完整备份恢复、Windows 打包、Excel `.xls` 导出、`.xls` 自动修复或旧账规则的无确认猜测。`.xlsx` 导出和 `.xls` 迁移的边界以 `docs/EXCEL_CONTRACT.md` 为准。
