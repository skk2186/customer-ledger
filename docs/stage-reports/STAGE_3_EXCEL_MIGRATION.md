# 阶段三：Excel 导出与旧账迁移

## 最终结论

**PASS**。本阶段在 `develop` 上完成 `.xlsx` 导出、旧 `.xls` 只读试算和经确认的迁移管线；未创建新分支、Pull Request 或远程提交。

## 修复与实现范围

- 新增 `export_service.py`，从 `calculation_service.py` 读取有效账务和派生数值，生成当前客户、客户汇总总表和全部客户账目的 `.xlsx`。
- 客户 Sheet 严格使用客户名称，固定 13 列、标题行、日期/数字类型和 `合计` 行；未分配收款余款以“预收款”独立行导出，保证分配实收与客户总收款不混淆。
- 新增 `legacy_import_service.py`，按 Parse → Normalize → Dry Run → Mapping/Exceptions → User Confirmation → SQLite Backup → Transaction → Reconciliation 实现旧表流程。
- 旧 `.xls` 使用 `xlrd` 只读解析；A:M 是正式区，N 列以后只形成异常；扫描不会在第一条合计行停止；历史汇总表只用于聚合核对参考。
- 确认导入前使用 SQLite Online Backup API；确认后的 Customer、Shipment、Payment、PaymentAllocation 和 ImportRecord 在一个事务中写入。来源键至少包含源文件 SHA-256、工作表和原始行号，支持同源幂等和哈希变化重导入。
- 导出和迁移入口已接入全中文页面；Dry Run 报告只写入被 Git 忽略的运行目录，不含客户名称、金额或备注明细。

## 导出验证

匿名合成数据通过 `openpyxl` 读回验证：客户明细固定表头、合并标题、Excel 日期类型、数值类型、签名欠款、预收独立行和页脚恒等式均通过；客户汇总页脚使用有效 Payment 总额，全部账目工作簿首个 Sheet 为 `客户汇总总表`。读回文件未发现公式、外部链接或宏结构。

## 旧表解析与合成验证

匿名生成的 `.xls` 回归覆盖标题、表头、日期业务行、空行、合计行后续业务行、N 列异常、预收候选、明确付款、冲突处理、未确认预收、备份失败、事务回滚、同源重复和文件哈希变化。Dry Run 断言正式业务表零写入；确认导入断言超额收款保留完整 Payment、只按允许金额分配，其余保持未分配预收。
